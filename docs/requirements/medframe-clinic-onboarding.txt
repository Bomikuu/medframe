# MEDFRAME — CLINIC INVITATION & ONBOARDING
## Complete Multi-Step, Resumable Clinic Registration Experience

Implement a complete invitation-based clinic onboarding system
for Medframe.

Medframe is a clinical management platform for healthcare
organizations, doctors, dentists, and patients.

Technology stack:

Frontend:
- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- React Hook Form
- Zod

Backend:
- Django
- Strawberry GraphQL
- PostgreSQL
- Django Authentication
- Django ORM

The onboarding system should allow clinics to register through
an invitation, configure their organization, create an account,
and start using Medframe.

IMPORTANT:

Do not create one long registration form.

Build a professional multi-step onboarding experience.

Users must be able to leave and return without losing progress.

Implement all related features in one cohesive development batch.

Preserve the existing Medframe design system, authentication,
organization models, and GraphQL architecture.

Do not implement the public clinic website builder as part
of this task.

==================================================
2. INVITATION SYSTEM
==================================================

Implement invitation-based clinic registration.

A Medframe platform administrator can invite a clinic.

Invitation fields:

- Clinic contact email
- Contact name, optional
- Clinic name, optional
- Invitation expiration
- Invitation status

INVITATION STATUSES:

- Pending
- Opened
- In Progress
- Completed
- Expired
- Revoked

Generate a secure invitation link.

Example:

medframe.com/onboarding/invite/[token]

The token must:

- Be cryptographically secure
- Be time-limited
- Be validated server-side
- Be revocable
- Prevent unauthorized reuse
- Be stored as a secure hash in the database

Do not expose sequential invitation IDs.

The invitation should be associated with
the intended recipient email.

Do not treat possession of a URL alone as
sufficient proof of identity for account creation.

Require email verification or an equivalent
secure identity-verification mechanism.

Provide appropriate handling for:

- Expired invitations
- Revoked invitations
- Invalid invitations
- Already completed invitations
- Existing Medframe users
- Interrupted onboarding

If the recipient already has a Medframe account,
allow them to authenticate and continue.

Do not force them to create another account.

11. RESUMABLE ONBOARDING
==================================================

THIS IS A CRITICAL REQUIREMENT.

Users must be able to leave onboarding
and return later.

Examples:

A clinic administrator completes:

- Introduction
- Clinic Information
- Specialties

Then closes the browser.

When they return, Medframe should restore
their progress.

They should continue from the last
incomplete step.

--------------------------------------------------
11.1 AUTOMATIC SAVING
--------------------------------------------------

Automatically save each valid step.

Support:

- Save on Continue
- Debounced autosave for appropriate fields
- Save and Exit
- Resume Later

Show saving feedback.

Examples:

Saving...

All changes saved

Unable to save changes

Never show a successful save indicator
until the server confirms persistence.

--------------------------------------------------
11.2 RESUME FLOW
--------------------------------------------------

Before account creation, use a securely verified
invitation and onboarding session.

An invited user should be able to resume
through the original invitation process or
a secure resume link sent to the verified email.

Do not depend only on localStorage.

Do not store passwords in onboarding drafts.

Do not place sensitive setup information
inside invitation URLs.

Use server-side persistence.

After account creation, associate the
onboarding draft with the authenticated user.

Returning users should see:

"Welcome back. Continue setting up your clinic."

Display their current progress.

Action:

Continue Setup

Optionally provide:

Start Over

Starting over must require confirmation.

--------------------------------------------------
11.3 DRAFT STATUS
--------------------------------------------------

Support:

- Not Started
- In Progress
- Awaiting Verification
- Ready for Review
- Completed
- Expired
- Cancelled

Track the current step.

Track completed steps.

Track last saved time.

Track the verified invitation owner.

Use expiration and cleanup policies
for abandoned onboarding drafts.

Do not allow another invited user to access
a draft they do not own.

19. SECURITY
==================================================

Invitation onboarding creates privileged
organization accounts.

Apply strict security controls.

Requirements:

- Cryptographically secure invitation tokens
- Hashed token storage
- Invitation expiration
- Revocation
- Email verification
- Rate limiting
- Replay protection
- CSRF protection where applicable
- Secure authentication sessions
- Server-side validation
- Organization authorization
- Audit logging

Do not grant administrator privileges until
the invitation and user identity are verified.

Prevent duplicate organization creation.

Do not expose invitation information
to unrelated users.

Validate uploaded logos.

Do not expose draft organization details publicly.

Keep onboarding data isolated from
clinical patient records.
