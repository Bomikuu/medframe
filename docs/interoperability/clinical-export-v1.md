# Native clinical export v1

`medframe.clinical-export/1` is a local Medframe JSON attachment, described by `clinical-export-v1.schema.json`. It is not a FHIR, HL7 or DICOM implementation and has no receiving-system compatibility claim. No import or outbound connector is supplied.

The staff user reviews an exact immutable consultation revision and chooses sections. Preview returns identifying metadata, section inventory, byte count, SHA-256 digest and a signed review proof valid for10minutes. The proof contains opaque identities, selection, timestamp and digest, not clinical text. POST download requires acknowledgement, the same user's native MFA staff session, current membership and patient grants. Station credentials and patient realm are denied. Revocation between preview and download denies the attachment. Proofs travel in request bodies, not URLs; no bundle is stored or publicly linked.

The envelope contains schema_version, fixed generated_at, source organization/branch IDs and recorded branch name, patient ID/clinic reference/name_at_export, revision ID/version/finalized time/author ID and the provider name/specialty captured at finalization. Patient display identity is current at export and explicitly labelled; a later identity change invalidates the reviewed digest. Names are not claims of credential verification. A revision's author ID remains its recorded author, even if the provider and author differ.

Sections are allowlisted: soap, diagnoses, observations, dental, anatomy and procedures. The first three are selected initially. Unselected fields are omitted, not empty assertions. SOAP preserves four recorded note strings. Diagnoses retain their recorded certainty and optional code without inventing a terminology system. Observations retain label/value/source; no unit or value conversion is performed. Procedures preserve recorded status, tooth/surfaces and notes without interpreting planned care as completed.

Dental contains this exact revision's findings and its preserved chart snapshot, including the source encounter for chart entries and recorded asset/point anchors where present. Anatomy contains the same revision's findings, registry version, structure, laterality, certainty/category and recorded model/map anchors. These references do not embed geometry or claim clinical validation. No current chart, later amendment or unrelated current history is merged into the attachment. Missing/unmappable selected data fails with UNMAPPABLE_RECORD rather than silently dropping the section.

Excluded: document/diagnostic binaries, document IDs/storage keys/signed URLs, billing/payment data, credentials and unpublished working drafts. Audit events store actor/organization/revision identity and digest in their action, never the body. Responses are application/json attachments with generic revision-ID filenames, private/no-store and sandbox/nosniff protections. Maximum serialized body5MiB. The caller should treat the file as sensitive patient information; the application does not transmit it to an external party.

The checked-in JSON Schema is generated from the typed Pydantic envelope. Breaking structural/semantic changes require a new schema_version and mapping document. A future importer must independently validate identity, provenance, code/reference support, duplicate handling and clinician review before any record mutation. Current exported JSON never automatically creates or changes a clinical record.
