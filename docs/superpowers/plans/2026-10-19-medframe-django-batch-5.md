# Medframe Batch 5 Implementation Plan

Execution: native in this chat, without subagents, delegation, or a fresh agent reviewer. The user approved the written design with “proceed”. The user approved this plan with “proceed”; native implementation was executed with the bounded results below. The user’s one-pass verification preference overrides per-task red/green execution: write the focused tests alongside each task, then run the accumulated checks once at the end. Tasks/commits are implementation order, not separate feature handoffs.

**Goal:** Complete doctor request → patient center selection → center examination/result submission → clinician review/explicit patient release, with revocable referral-specific access.

**Architecture:** A new Django diagnostics app owns cross-organization partnerships, requests, assignments, immutable results and reviews. Existing staff MFA, separate patient realm, private DocumentVersion storage/scanning, audit, idempotency, pagination and portal releases remain authorities. GraphQL adapters feed focused shadcn/Tailwind clinic, center and patient screens.

**Tech Stack:** Existing Django/PostgreSQL/Strawberry/Celery/Redis, S3-compatible private storage/ClamAV, Next App Router/TypeScript, RHF/Zod, shadcn/Radix/Tailwind/Lucide. No new external service or product dependency is planned.

**Spec:** `docs/superpowers/specs/2026-10-19-medframe-django-batch-5-design.md` (approved October 19, 2026).

## Global constraints

- Native only; preserve current `.next-batch4`, original database/accounts/MFA and tag `checkpoint/pre-batch5-2026-10-19` at `33f0950`. Branch: `codex/django-diagnostics-batch-5`.
- “Allow JPEG, PNG, WebP and PDF up to the existing 20 MiB limit.” Reject DICOM/archives, arbitrary file URLs and active PDF content. Preserve clinical image bytes/framing.
- “Input limits: test name 160 characters, region 120, clinical question 4,000, instructions 2,000 and at most 20 selected file versions.” Result report: 12,000 characters; external accession: 120; result attachments: 20. Default list/history size 20; hard cap 50. Tickets expire after 60 seconds.
- Existing finalized encounters and submitted results/reviews are immutable. No inferred diagnosis, automated clinical edits, live messaging, money transfer, image measurement, DICOMweb/FHIR conformance or public deployment.
- Patient selection uses live PortalLink; center reads use current membership/organization/partnership/assignment/sharing. A signed ticket never replaces those checks. Do not submit private data to Jev.
- Staff center operators receive no clinic patient-directory/clinical/billing permissions. Clinic administrators can manage partnership metadata but receive no referral contents automatically.
- Read applicable Next.js guides before UI code; use existing tokens and actual shadcn/Radix owners, focused readable modules, Prettier/Ruff, grouped expected-input fields. No unrelated deferred-issue repairs.

## Review focus

1. An old download ticket or replay key must fail after partnership suspension, center reassignment, account/link revocation or sharing withdrawal: pin in `test_diagnostics_scope.py` / `test_diagnostics_files.py` / `test_diagnostics_portal.py`.
2. Result submission racing cancellation/recall must serialize, never attach to a revoked assignment: pin two-connection tests in `test_diagnostics_workflow.py` and scope-lock tests.
3. A correction after review must require a new review while preserving exact earlier report/review/release versions: pin in `test_diagnostics_results.py` / `test_diagnostics_portal.py`.
4. Diagnostic-purpose files must not fall through branding permissions/resizing or a generic clinical download route: pin in `test_diagnostics_files.py`, retaining real `test_documents.py` and `test_branding.py` regressions.
5. Wrong-context users, stale pagination cursors, duplicate submits and pending/rejected/unavailable scans must not expose data or create misleading completion states: pin in scope/results/API tests and the paced browser journey.
