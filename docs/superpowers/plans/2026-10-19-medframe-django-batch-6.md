# Medframe Batch 6 Implementation Plan

Execution: native in this chat, no subagents/delegated reviewer/separate chat. User approved the written design with “approve”; this written plan awaits review. One accumulated verification pass replaces per-task red/green loops under the user’s standing preference. Necessary activation-blocker repairs and focused confirmation are authorized, and local activation is automatic. No separate execution-method or activation question is needed.

**Goal:** Ship a model-first body/skeleton annotation workflow inside consultations, with preserved patient-side semantics, exact history/comparison and explicit patient releases.

**Architecture:** A focused Django anatomy domain owns registry/asset validation, finding identities/indexes and immutable chart snapshots; existing EncounterDraft/EncounterRevision remain the write/finalization authority. Existing Three.js/R3F and shadcn/Radix compose an accessible editor using the same RHF form owner. Patient releases freeze explicitly selected anatomical evidence rather than exposing the live chart.

**Tech Stack:** Existing Django/PostgreSQL/Strawberry, Next/TypeScript/RHF/Zod/Tailwind/shadcn/Radix/Lucide, React Three Fiber/Three.js. Only an offline geometry converter may be needed; no new cloud/runtime service.

**Spec:** `docs/superpowers/specs/2026-10-19-medframe-django-batch-6-design.md`, approved October 19, 2026.

## Review focus

1. A front/back/side camera change or negative source transform must not swap patient-left/right; pin this in asset mapping/registry tests and the browser before/after rotation.
2. A replaced/missing historical GLB must not relocate saved pins to the new version; pin old-asset rendering selection/fallback and immutable snapshot/release assertions.
3. An old consultation/template or dental-only save must not erase anatomy, nor anatomy-only completion erase dental/SOAP; pin aggregate/default/template and amendment regressions.
4. Copied finding keys, stale source-revision carries, invalid mesh/layer/bounds and revoked access must fail in Django; pin validation/authorization/optimistic-conflict tests.
5. Failed WebGL/model fetch, hidden tab and expanded-editor exit must retain the same draft and allow keyboard/2D editing/save; pin one paced desktop/mobile failure-path journey.
