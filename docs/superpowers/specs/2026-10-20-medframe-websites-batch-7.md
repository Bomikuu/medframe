# Batch 7 — personalized clinic websites

User-authorized roadmap scope: Django Edition sections 23 and 30. Native execution, multiple connected features and standing local activation apply; no external deployment or DNS changes are authorized. Preserve the original data and the pre-existing uncommitted clinic-shell width change.

Build a clinic-administrator website editor, structured templates/sections, explicit draft saves, responsive preview, version conflicts, immutable publication snapshots, history/restore-to-draft, unpublish, public routes and SEO. Public material is separately authored and explicitly approved; never join patient records or clinical files into a website. Provider biographies/services are manual public copy, not automatic credential claims. Defaults contain the actual organization name and otherwise empty factual fields. No fake testimonials, ratings or stock patient faces.

Use `/clinic/settings/website` for the editor and `/clinics/[slug]` for published pages. Offer general-practice and dental presentation templates, an identity/hero, about, services, team, hours/contact and optional queue section. Order/visibility are keyboard-operable. Fonts/colors come from bounded choices; arbitrary HTML/JS/CSS/URLs are forbidden. Images use a new website-only purpose on the existing private scan/upload pipeline. Only clean explicitly published website/logo image versions are anonymously readable, and only while referenced by the live published snapshot. Preview reads remain authenticated. Snapshot history is append-only; restoring creates an editable draft without silently republishing.

Publishing requires native staff realm/MFA, organization.manage, expected version, public-content acknowledgement and server validation. A publication is a local application state transition, not external hosting. Public HTTP reads return only the last published snapshot and optional number-only live queue for an explicitly selected clinic branch. Draft edits do not change it; unpublish immediately denies page and asset reads. No-store reads prevent cached withdrawn snapshots. Patient CTA opens the existing authenticated patient portal, without creating access or introducing public booking identity lookup.

SEO includes title, description, canonical path, Open Graph text, index preference, a published-only sitemap and safe public business JSON-LD. Draft preview is noindex. Slugs are unique, validated and remain fixed after initial publication to avoid breaking links. No tracking scripts or public clinical APIs.

Custom domains have an ownership challenge, explicit DNS TXT verification and a verified mapping for the public renderer. DNS/TLS/hosting changes require the operator and are not performed here. Unverified domains never route a site; matching a domain never authorizes staff or patient APIs. A canonical application-origin public path remains available independently. Local activation must not publish an original clinic automatically.

Bounded evidence: focused permission/tenant/version/publication/asset/domain tests, build/type/format/lint/drift, one isolated synthetic desktop/phone browser pass and at most one focused activation confirmation. Log unrelated findings. Fresh encrypted checkpoint/isolated restore, original row and storage fingerprints, additive migrations only, then start the local artifact. Use Graphify/Jev honestly with sanitized judgments and no private clinical data.
