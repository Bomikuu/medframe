# Doctor workspace and device management amendment

The user requests native implementation now: clicking a device opens a modal with editing and code regeneration; access codes belong to the doctor rather than a single consultation; the tablet can choose any authorized patient/consultation or begin a walk-in and collect identity at the end. This directly authorizes the connected implementation and local activation. No subagents or repeated approval handoffs.

## Design

Retain setup pairing/physical verification separately from named clinical identity. Add doctor-issued five-minute single-use codes and short native sessions, bound to issuer, full MFA source session, organization, branch and approved device. Existing exact-encounter sessions stay restricted. Doctor sessions permit clinical patient discovery, creation and clinical work only through native permissions and explicit patient grants; no administration, authentication changes, further delegation or automatic billing authority. Absolute thirty-minute expiry, ten-minute API inactivity, source/device/account/membership revocation remain enforced. Codes store digests only.

A doctor generates their own code from Station home (also linked from Devices & Stations), never an administrator impersonating another doctor. Receiver opens Station home, not an encounter. Existing-patient selection uses authorized search and opens patient care/history or a new consultation. Existing consultation selection retains editing ownership: explicit same-doctor control transfer requires current version and lease generation, invalidating the former writer; it requires no consultation access code. Cross-clinician responsibility transfer remains a separate explicit workflow.

Default new care is an unnamed, memory-only walk-in draft using the existing SOAP/diagnosis/procedure, dental and anatomy form contracts and editor components. No placeholder patient or competing persistent clinical aggregate. History/allergies remain visibly unknown. Before saving, choose an authorized existing patient or enter minimal new-patient demographics and the reason/branch. One idempotent transaction validates identity and clinical content, registers if permitted, creates the existing encounter aggregate and saves the draft. On failure nothing commits and form content remains in memory. Link first for documents, treatment plans, longitudinal history or financial activity; clinical finalization follows the existing review flow after linking.

Clicking a device name opens one management dialog. Edit name/branch/mode/capabilities with optimistic version checks and server validation. A scope change revokes credentials/pending pairing and requires pairing/approval again; renaming preserves pairing. Regenerate pairing is available in every state and explicitly warns that existing device access ends. Codes are displayed once with expiry. Polling must not overwrite the user's form edits.

## Review and verification

Source and existing Graphify code corpus are inspected before changes; refresh relevant code corpus afterward. Jev receives sanitized architecture only; connection failure is recorded rather than treated as a judgment. Targeted backend permission/replay/revocation/identity/atomicity/ownership cases plus production build, scoped lint/Ruff and one browser flow. Log unrelated findings, repair activation blockers only as authorized. Preserve source/build, encrypted database checkpoint/verified restore and original row fingerprints before additive migration. No original credential/MFA changes or review-data import.
