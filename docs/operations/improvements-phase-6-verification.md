## Implementation

- Existing administrator-only Staff snapshot exposes current native role-permission metadata and safe configuration facts. - Own membership/role/branch/workspace/billing selection is read-only in Manage staff, matching the existing SELF_ACCESS rule. Name/contact/photo fields remain separate. No original roles, grants, credentials or MFA changed. Existing save/version/last-administrator controls remain authoritative. Circular staff photo controls and existing scanner owner are retained.
- Delivery & online appointment setup is a progressive disclosure in Staff & Access, under the same organization.manage authorization. It distinguishes local Mailpit capture from configured SMTP, separately reports SMSGate registration configuration versus reminder preview/live flag, and reuses public-safe call connection_summary. No SMTP host, gateway address, credential, media URL or secret is returned. No network probe runs. Configuration is explicitly not proof of sending, delivery, HTTPS trust or internet connectivity. Authorized administrators can open the existing reminder delivery-state log; this is not a new per-invitation mail delivery tracker.
- Fresh platform-authorized clinic create/replacement responses return the just-generated link so the same accessible copy/manual-fallback dialog can show it. The invitation list remains hash-only and does not reveal tokens. Existing idempotent duplicate issuance returns metadata without recreating/exposing an old token; a lost response still requires the existing email/replacement recovery. No new token persistence, schema or migration. Existing generation/version/expiry/revocation and contact proof remain intact. No invitation is created or replaced as a side effect of opening a page.
- Staff invitation rows distinguish pending, expired, accepted and revoked next actions. Copying an unused staff link reuses the existing native retrieval. Queued email is not labeled delivered. Clinic paused setup explicitly distinguishes saved clinic details from unsaved password/verification state. Actual server-side local-mail detection supplies the clinic verification inbox link, replacing the NODE_ENV-only assumption.
- Patient pending/accepted/declined presentation names the next action, retains a copyable request reference, explains clinic review and later portal activation, and says registration does not book an appointment. Native submission/review/identity/account owners are unchanged. Reviewer dates use the existing calendar-date formatter; acceptance copy says queued invitation rather than guaranteed inbox delivery.
- Step changes move focus to clinic/staff/patient headings; staff modal dismissal returns focus to its connected opener. Switches have explicit accessible names, clinic progress buttons name current/completed/locked status, long clinic names wrap, and touched success/identity surfaces use semantic teal tokens. Existing reduced-motion CSS and password guidance remain; no new animation or credential flow.
