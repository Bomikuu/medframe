### Local clinical JSON export

The consultation's preserved-revision action opens a section/revision review before local download. `medframe.clinical-export/1` is documented with a generated typed JSON Schema under `docs/interoperability/`. It is not a FHIR/HL7/DICOM implementation or an import/receiving-system claim. Default selected SOAP/diagnoses/observations and optional dental/anatomy/procedures map only one exact immutable revision and its saved chart. Names at export versus captured provider/branch metadata are explicitly differentiated. No live draft/later amendment/unrelated current history, private object keys/URLs, documents, payment entries or login material enter the envelope.

Both preview and download require native staff realm/MFA, existing encounters.write/documents.write plus require_encounter's live clinical patient/branch grants. Station/device/delegated and patient-realm requests are denied. A dedicated signed10minute proof binds user/organization/encounter/revision/sections, fixed generation timestamp and digest. Download freshly authorizes, regenerates and compares that digest; identity changes require a new review and revoked access denies the attachment. Acknowledgement is mandatory. Only allowlisted POST proxy paths were added, retaining origin/CSRF/body limits and existing GET file behavior. Tokens travel in request bodies, not URLs; attachments use generic identifiers, sandbox/private/no-store/nosniff headers and5MiB bounds. Audits store identities/digest rather than PHI bodies; no durable/public export bundle or external data transfer.

Optional AI remains the existing visibly disconnected shared drawer with disabled send/attachments. No external AI, vendor EHR connector, live messages, automated financial movement or public deployment was added. This delivers the approved local Batch8 scope, not those unselected integrations.
