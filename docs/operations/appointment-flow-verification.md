Input accepts no date/slot/duration; a server creation timestamp and one-microsecond ordered end anchor satisfy existing appointment storage constraints. These are record anchors, not availability promises or room deadlines. No Reservation or queue ticket is created. The linked AppointmentRoom uses existing Instant timing and manual closure. Native event/audit owners record creation. Cancel/completion/identity/access checks and doctor admission remain unchanged. Clinical notes are not automatically created/finalized.

Request receipts retain a stable client request ID across retries. Provider/patient advisory locks and existing-open-room checks reuse the same live room for the same branch/provider/patient or reject conflicting open instant rooms. Existing clinical authority is rechecked before reuse. This is source-reviewed behavior, not a tested concurrency/security claim. Scheduled booking slot checks/reservations are unchanged. Instant rows expose explicit timing metadata; primary calendar/day/agenda/details labels use Instant. Queue check-in and scheduled rescheduling reject instant rooms with actionable errors rather than interpreting recording anchors as visit duration.
