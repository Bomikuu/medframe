## Native data and chart behavior

The existing ClinicInsights JSON response now includes prior daily series for appointment/queue/encounter metrics and a patient section. Patient totals and registration dates derive from existing scoped_patients, selected branch, live native staff membership and permitted demographics/clinical access; directory-only staff can obtain only their permitted demographic aggregates. No patient rows/identifiers are serialized. Operations/clinical/financial sections remain independently gated. Total patients is explicitly a current accessible-record snapshot, not an all-clinic count for a provider with limited grants or a historical stock comparison. New registrations use created_at. Scheduled bookings are grouped by scheduled date, not booking creation. Existing status semantics and consultation-vs-department queue separation remain.

CSV now supports the permission-gated patient aggregates and prior-period activity daily values. No GraphQL SDL/codegen is needed: the existing field is native JSON. No models, migration, roles/credentials/MFA/grants or financial ledger changes.

Shared PeriodComparisonChart renders solid teal/current and dashed gray/previous lines aligned by day of period, explicit date-range legends, selected-date values, pointer inspection, keyboard/touch range control and expandable exact tables. Bookings/queue/consultation selection and registration trends use it; financial net payments reuse the same renderer with native currency formatting. Financial activity compares completed clinic dates; outstanding/due/overdue remain separate as-of-now amounts. Existing 1–366 completed-day/custom/equal-prior-period policy stays authoritative.
