# Instant consultation rooms — October 21, 2026

The user approved an instant consultation room: doctor opens access, shares a PIN, and ends the room manually. Implemented as a bounded timing option within existing appointment rooms. An existing booked/checked-in appointment binds the patient, branch and provider; this phase does not create appointment-free walk-in visits or alter calendar reservations.

## Behavior

New rooms offer Scheduled or Instant. Existing scheduled-room access can be explicitly reset as Instant with confirmation and a new PIN/generation. Only an eligible authenticated clinician with the existing appointment-management and clinical authorization can create/reopen Instant access. Existing rooms migrate to Scheduled. Scheduled timing remains unchanged. Instant bypasses clock-based entry/start/end only; identity, branch/provider changes, cancelled/completed/no-show appointments, explicit end, PIN, source-session and patient-admission checks remain authoritative. A clinician leaving does not end the room; explicit End closes it for both participants. Manual rooms do not reserve additional calendar time or automatically finalize notes.

Native summaries identify timing mode. Instant views show immediate PIN admission context, manual closure and no countdown/Add time/reschedule prompt. Cookies renew with a 24-hour browser-session lifetime on snapshots; this is not a room deadline. Existing request/socket reauthorization controls actual access. Shared-model Redis state uses the same renewable cache lifetime; it remains ephemeral and can reset after inactivity.
