October 23, 2026. Implemented together from the approved module audit, natively in this chat, with no subagents. ## Delivered scope

- Portal Home now leads with the next eligible appointment, own current consultation queue, currency-separated issued-invoice obligations and action links, above explicitly released records. The new read-only `patient_task_home` projection reuses native portal-link authorization, appointment serialization, patient operations and financial installment calculations. Current obligations include all scoped issued invoices, rather than the displayed billing page. Future obligations remain distinct from due/overdue amounts. This does not add clinical release, payment or registration authority.
- Communications distinguishes SMSGate verification configuration from the separate reminder transport, and local invitation-email capture from external delivery. Delivery-state explanations distinguish scheduled, preview, provider accepted, delivered, failed, cancelled and unknown. Accepted is not delivered; delivered is not read; unknown does not invite a duplicate retry. Existing mutation/retry owners remain authoritative. Status filtering has a non-sensitive URL value; cursor history stays scoped in memory.
- Pending onboarding logos use serialized backoff at3/6/12/20/30/30seconds, at most six automatic requests per cycle. Unavailable/other non-pending states do not poll; manual checking is explicit. Logo identity/state changes cancel scheduled continuation. The existing draft/bootstrap owner remains responsible for accepting snapshots. Verification copy says a code was requested/queued, without claiming receipt.
- Call information separates audio/video, shared-model and room-access facts. Shared-model participation has a persistent view-only/pointing explanation and controls using existing doctor permission/local patient choice. Recovery offers the existing rejoin/audio-only paths where allowed. No expiry, admission, session or permission policy is relaxed.
- Account settings explains personal versus clinic-owned settings and effective access. Specialty cards preview actual built-in SOAP/observation starters, labeled Medframe content revision1, distinct from saved clinic template revisions and doctor credentials. Website publication review describes contacts, visible sections/images, indexing, portal and public-queue scope before the existing explicit publish confirmation. Server version/asset validation remains authoritative.
- The encounter editor delegates documentation panel composition into a focused component. Dental/anatomy code and children mount on first selection, then stay mounted after visiting, under the same form/autosave/version/lease owner. Existing initial specialty view is preserved. This is an implementation change with bounded visual evidence, not a measured GPU/network performance result.
- `scripts/backup-retention-report.py` inventories existing recorded checkpoint metadata and encrypted-file checksums without decrypting, restoring, deleting or starting services. Policy protects baseline/latest recorded restores/table-inventory milestones/unknown items/private storage. Table inventories are not full schema equivalence; every candidate needs manual source/configuration/recovery review. The one inventory reported92 items and1 review-only candidate. Nothing was pruned and no fresh restore is claimed.
