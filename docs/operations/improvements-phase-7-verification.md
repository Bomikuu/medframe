## Implemented

- A focused request-failure classifier reads native GraphQL error extensions or the JSON transport body before HTTP fallbacks. INVALID_CSRF/INVALID_ORIGIN no longer become FORBIDDEN solely because their status is403. Unknown403 says request rejected; actual FORBIDDEN/NOT_FOUND/UNAUTHENTICATED/STATION_REQUIRED still retain their own access/session semantics. ApiError is classified explicitly. No raw response/query/variables are displayed.
- The existing recovery container distinguishes request-security rejection, secure-check unavailability, rate limiting and malformed response, alongside real access/expiry states. Security rejection does not label a patient record unavailable or add sign-out recovery. Try again remains an explicit owner callback; no write is replayed or authorization weakened.
- Native staff/portal CSRF routes use the same Django get_token/cookie owner. Only pending GET token acquisition is shared across callers in one browser document, with an8-second bound. Settled tokens are discarded; no persistent cache crosses authentication changes. A caller can detach through its abort signal without cancelling another caller's shared GET. Staff/portal/onboarding GraphQL middleware forwards the request signal. Backend CSRF/origin/session/MFA/cookie rules remain unchanged.
- Shared read refresh serializes an active request and retains at most one queued invalidation rather than aborting repeatedly on focus/retry. Queued refresh is retained so a post-mutation invalidation is not silently lost. Scope/generation cleanup still aborts/drops old work; native authorization rejection and any HTTP401/403 still clear old scoped data, even when precise copy identifies request-security validation. Existing operations manual-refresh policy remains.
- An invalid Billing setup response now produces explicit INVALID_RESPONSE recovery instead of a permanent loading state with no error. No invoice/filter/ledger mutation, financial permission or backend calculation changed.
- Continue setup from the paused clinic screen now reads native bootstrap and revalidates its saved proof/draft. Valid proof resumes saved setup; native ACCOUNT_REQUIRED or VERIFICATION_REQUIRED goes to the appropriate existing step, and closed invitation states stay distinct. Retry failure stays visible on the paused page. No cached-proof bypass, renewed role grant or new verification method.
- The logged narrow staff-terminal Find button has the persistent accessible name Find patient, retaining the visible compact icon/desktop label.
