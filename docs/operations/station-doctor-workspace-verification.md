# Doctor Station workspace — October 19, 2026

## Active locally

Branch `codex/station-doctor-workspace`, implementation `4b75529`, production artifact `.next-station-doctor`, build ID `2jsn-6rZCb84bPpvNrwSb`. Original `medframe_django` and local API/worker/beat are active. This implements the user's doctor-wide access/device management/walk-in amendment natively without subagents.

Use:

1. Open `/clinic/settings/stations` and click a device name or **Manage**. The modal edits name, branch, purpose and functions, and offers **Regenerate pairing code** in every state. Regeneration ends old device access. Enter the replacement code on public `/station`; **Refresh connection** inside the modal shows the pending physical device, then compare the verification phrase and approve. Renaming preserves pairing; changes to scope revoke credentials and require re-pairing/approval. Unsaved form edits are not replaced by the table's polling.
2. On the doctor's authenticated workstation, open `/station/clinician` and choose **Connect my device → Generate doctor code**. Select the permitted branch. A clinic administrator cannot generate a code impersonating another doctor; the issuing account needs its own provider profile and clinical permissions. Devices & Stations links to this workspace.
3. On the approved tablet, enter that doctor code under **Open doctor workspace**. There is no per-consultation login code. No receiving password/MFA prompt is required. The home offers **Start walk-in consultation**, **Choose patient**, and paginated permitted consultations including historical records. Patient selection opens demographics, clinical context and paginated consultation history. Existing native grants and the device branch apply; this is not unrestricted clinic access.
4. For a walk-in, the shared real 3D dental/anatomy editors, SOAP, diagnoses and procedure controls operate on a memory-only provisional draft. **Confirm patient & save** asks for an authorized existing patient or minimum new-patient details, branch and reason. Identity and clinical content commit atomically into the existing patient/encounter aggregate, with idempotent retry and no placeholder patient. The original review/finalization workflow opens afterward. Unconfirmed allergies/medications/history are visibly unknown. Refresh/session end discards unnamed unsaved work; no offline persistence is claimed. Link identity first for longitudinal history, documents, treatment plans or billing.
5. Opening a consultation does not silently overwrite another device. A doctor-code session can explicitly **Move editing to this device**, with current version/lease generation and a warning that only saved content moves. The old writer loses server save access. Other doctors' ownership cannot be taken with this action. Responsibility transfer to a different named clinician remains a separate accepted handoff, not an anonymous access code.

Doctor codes are five-minute, digest-only, one-use and attempt-limited. New `DoctorAccessCode`/`DoctorStationSession` extension tables bind the receiving native MFA-authorized staff session to the named issuer/provider, source session/account epoch, clinic/branch and approved device. Maximum thirty-minute absolute expiry and ten-minute API inactivity remain; polling counts as API activity. Source session revocation/expiry, account epoch, live membership and device checks continue. The source's password/MFA/roles are unchanged. A restricted tablet cannot issue further codes, administer settings/users, change authentication or inherit financial authority. Clinical services keep patient grants, aggregate versioning, immutable revisions and document ownership checks. Native clinical treatment-plan permissions remain available; they do not grant billing permissions. Existing exact-encounter `StationAccessSession` records retain their old strict boundary.

Patient-kiosk self-service/department queues, configured online payments and live TV content remain later Station phases. No AI integration, live messages, online money movement, physical OS lockdown or public deployment was added. A reachable HTTPS clinic origin/network remains operator configuration for real tablets; localhost demonstrates the application flow.
