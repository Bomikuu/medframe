# Medframe application improvement audit — October 22, 2026

## Result and scope

Prioritize reliable transitions, truthful session feedback and completion of connected workflows. Preserve the existing Medframe visual system, grouped patient profile, patient-action hub, shared charts and native mutation owners. A second full visual reconstruction is not justified by this audit.

This is an audit and phased proposal only. No product source, database, permissions, credentials, runtime configuration or integrations were changed. No builds, automated tests, lint/typecheck suites, mechanical UI detector, benchmarks or subagents were used. The standing visual-only instruction supersedes the skill's detector/testing defaults. Impeccable's context launcher failed earlier in this session and was not rerun; existing PRODUCT.md, DESIGN.md and the audit playbook were read directly. Writing-plans supplied the phase structure, adapted to native execution and visual verification.

Evidence consists of current source inspection across shared UI, terminal identity, patient profile, operations, calls, finance, services, onboarding and staff; focused Graphify relationships; a bounded read-only public-screen visual pass; and explicitly identified historical verification records. No authenticated clinic session was available in the browser. Protected Dashboard, Patients, Schedules, Billing and editor routes were source-reviewed, not freshly exercised end to end. The preceding terminal implementation's synthetic visual evidence remains separate, dated evidence in terminal-workflows-verification.md.

## Proposed improvements, not diagnosed defects

1. **Calls refresh efficiency:** useCallRoom uses socket-driven refresh plus a five-second visible-tab snapshot interval. Make revision-aware/coalesced refresh and disconnected fallback a measured optimization task; no current latency/load benchmark was collected. Preserve expiry, admission and permission rechecks.
2. **Clinical overview hierarchy:** preserve the five existing patient groups and action hub. Tighten the initial view around actual alerts/history review state, current visit, recent consultation and next step; do not introduce invented clinical alerts or another dashboard.
3. **Financial next steps:** graphs and exact comparison tables already exist. Add permission-scoped drill-downs from overdue/current-receivable summaries to the existing invoice/service collection with filters retained, plus a clear installment schedule preview before issue. Do not add another parallel reporting page.
4. **Setup readiness:** show administrators the real delivery/invitation/call configuration state and resumable next steps, with local Mailpit distinguished from delivery to a real inbox. Do not send messages or activate public hosting as part of UI work.
