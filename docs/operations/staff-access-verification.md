## Implemented surface

Settings → Staff & Access (`/clinic/settings/staff`) is visible only with native organization.manage. The directory has circular portraits/initials, role/title, branch, active state, workspace and billing summaries; search and All/Active/Station-only filters. Manage and Invite are separate dialogs. Administrative lists are bounded at200members/100invitations, branch-scoped for a branch administrator. Source is split into directory, modals, access fields, client, photo control and onboarding modules.

Managers edit the per-clinic display name/contact, membership active state, branch, supported clinic roles, full role-permitted tools or approved-Station-only mode, and independent billing None/View/Record payments/Manage levels (or preserve role defaults). Doctor/dentist selections create/update the existing ProviderProfile specialty/title used by consultations. Credential status is retained. Existing provider/history records are not deleted when roles change. Appointment resources/hours remain owned by the existing Schedules page, linked from Staff & Access; no separate scheduling engine is introduced.

Private photo controls upload one JPEG/PNG/WebP, sanitize/re-encode with the existing raster validator and scan with the existing scanner before storing/selecting it. Max2MiB/2048px. Selection is automatic after success, circular in UI, with remove. Pending onboarding and active membership portraits use authorized same-origin streaming; images are not public and no stock/fabricated people were imported. Existing staff show initials until an actual photo is supplied. Uploaded photos save immediately; other manager form changes/removal require Save. Staff profile edits do not rewrite the global account name/password/MFA.

Invitations are issued for3days, recipient-bound, one-use, revocable and encrypted for administrative link reopening/copy. Regeneration invalidates the previous link/code/proof and binds the new issuer. Copy does not require regeneration. Link/email-code payloads use the native encrypted MailOutbox; delivery depends on configured mail. The public `/staff/onboarding/[token]` flow verifies the invited email with six separate OTP slots (10minutes, bounded attempts/resends), saves a resumable profile/optional portrait, then authenticates an existing account or registers a new one under the native password policy and native MFA. The local-only Mailpit link is exposed under the same existing development configuration guard. Contact verification lasts30minutes; an interrupted challenge can restart without resetting existing MFA.

Google is available through the existing configured Identity Services component and native claims verification. Existing identities must already own the verified Google subject; email matching alone does not link an existing account. New Google identities may resume native MFA with an unusable password; membership is still withheld until final activation. Google is optional/configuration-dependent; no real OAuth transaction was performed in verification. Existing authenticated invited staff may accept under their own native MFA session. A different signed-in identity is rejected rather than silently signed out/switched.

## Authorization and preservation

Organizations StaffProfile/StaffInvitation/StaffPhoto are additive. A missing profile preserves original role behavior. `permissions_for` applies only per-membership billing settings and `require_membership` checks those effective codes, existing organization/active membership and device policy. Global Role.permissions is not rewritten. Platform/other roles cannot be assigned by this screen and are retained when editing supported clinic roles. Explicit Manage billing does not add refund/adjustment powers unless the existing roles already hold them.

Station-only is enforced in membership policy, not only navigation. Live approved clinician-device context is required for clinical work; existing approved-kiosk operational assistance remains limited to its native endpoints/permissions. Unpaired/revoked/wrong-clinic/wrong-branch devices cannot satisfy the policy. Device function restrictions and exact/delegated Station scope remain authoritative. All-Station memberships route to `/station` (`station_staff` navigation kind); a user with another full-workspace membership may still use that other clinic, while the restricted clinic rejects regular requests. The signed-document context marker supports authorized Station images/downloads; it only selects additional restrictions, never supplies identity/permission. Existing native sign-in/device pairing coexistence is preserved.

Management blocks self access/role/branch/status changes (profile changes remain allowed) and guards the last active full-workspace clinic administrator. Writes lock/authorize target membership or invitation, check versions, and audit. Existing patient grants are never created, widened or bypassed. Invitation activation rechecks current issuer authority (with issuer membership lock), branch/configuration, exact recipient and proof, then atomically creates membership/profile/provider after MFA. Existing memberships are managed rather than overwritten by another invitation. Invalid/replayed/revoked/expired invites do not grant access. These are implementation properties from source review, **not claims of exercised security acceptance**.
