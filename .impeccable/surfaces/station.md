# Station

Mode: Operate. Ordinary extension of Medframe's existing visual world.

Thesis: a clinic device should open directly into its assigned task while preserving named identity and clinical ownership.

Use the established palette, fonts, shared shadcn controls, generous touch targets and visible patient/save/connection context. Device table and pairing are task surfaces; clinician Station reuses the current real chart/editor. Public pairing has no patient context. Paired modes awaiting later phases show an honest setup state. No new brand tokens or raster assets are needed.

Phase 1 acceptance: paired approved clinician device, native sign-in, same saved consultation with restored chart selection, explicit acceptance, old writer blocked, lock/revocation and responsive code entry. Actual results will be recorded in `docs/operations/station-phase-1-verification.md`.

Active: `.next-station`. Inline source/visual review used the existing system; no global token or component-system change was required. Eight successful captures have no page overflow. Core pairing/approval and same-record tablet handoff pass across the documented initial and focused browser runs. Remaining layout/coverage follow-ups and Graphify extraction gaps are recorded in the phase evidence; they are not canonized as new design rules.

Code-access amendment: `.next-station-code` uses the same shadcn code blocks and incumbent world. Approved tablets show an access-code form instead of a sign-in demand. A measured identity/expiry strip reserves space above full-screen editors and provides End session; broad navigation is absent in delegated sessions. Four successful desktop/tablet/phone captures establish no page overflow and actual no-login entry. The bounded browser confirmation stops after a successful save at a duplicate status locator; further browser assertions are deferred in `docs/operations/station-code-access-verification.md`. Existing tall tablet notes/context headers remain an observation, not a new design rule. DESIGN.md and its sidecar were preserved.

Doctor workspace amendment: device names/Manage open a shared edit-and-connection dialog. A doctor generates their own workspace entry code on Station home. Provisional walk-ins reuse the clinical form and chart components; identity is confirmed before the atomic patient-linked save. Current desktop/tablet flows have native visual/interaction evidence; 390px home-action overflow is logged as STATION-DOCTOR-002 and left deferred. No global visual tokens or AI integration changed. Actual activation evidence is in `docs/operations/station-doctor-workspace-verification.md`.

Tablet gallery amendment (Operate): clinical-day clock, touch actions, patient portrait gallery and a narrower upcoming-care rail use the existing world. Today/All preserve record access; timing labels follow recorded facts. Shared scanned patient-image bytes remain protected and fully framed, while profile controls/previews are circular. Initial desktop/landscape tablet/portrait tablet/phone captures and focused tablet/phone confirmation have no overflow; this requested replacement supersedes STATION-DOCTOR-002 on the new home. End session asks explicitly and remains available inside Station dental modals. A non-blocking editor-navigation DOM error is logged without a further polish loop. DESIGN.md and its sidecar remain unchanged.

Patient self-service Phase 2 adds a separate four-action touchscreen kiosk at `/station/kiosk` and an authorized Patient Stations department board. See `.impeccable/surfaces/kiosk.md` for its privacy/verification/task contracts. Clinician tablets and existing editor identity/ownership behavior stay unchanged. Digital provider payment and TV remain the next phase.

Device-code refinement: the device table exposes separate Manage and Pairing code actions. Manage owns settings, physical approval and revocation; the pairing modal owns explicit confirmed generation/regeneration and a shared clipboard control. Opening the code modal has no mutation. Codes use existing type, muted panel and shadcn controls, expire visibly and are not recovered after closing. The shared temporary-code component also adds copying to doctor and responsibility handoff codes. No design tokens, authentication or backend ownership changed. Actual staged evidence and activation are in `docs/operations/device-code-modals-verification.md`.
